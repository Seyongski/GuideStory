## 1. 조달 원칙 — 하이브리드

### 1.1 판단 기준

부품마다 두 질문을 던지고, 답에 따라 조달 방식을 정한다.

| 질문 | "예"면 | "아니오"면 |
|---|---|---|
| ① 이미 잘 푸는 기성 모델이 존재하는가? | 가져다 쓴다 | 직접 만든다 |
| ② 그 능력이 **내 도메인 데이터에서만** 나오는가? | 직접 만든다 | 가져다 쓴다 |

②가 ①을 이긴다. 기성 모델이 있어도 내 데이터가 본질이면 직접 만든다.

### 1.2 부품별 조달 결정

| 부품 | 조달 | 근거 |
|---|---|---|
| 도형 생성 모델 (CVAE, v1) | **자체 설계·학습** | "메이플풍 타일로 하트를 그리는 모델"은 세상에 없다. 가져다 쓸 대상이 존재하지 않는다 |
| 자기회귀 트랜스포머 (v2) | **자체** | 아키텍처는 표준이지만 토크나이저·학습·추론을 직접 구현한다. "내가 만든 초소형 LLM"의 실체 |
| 조건부 레벨 생성 모델 | **자체** | 조건 공간(`MapSpec`)이 내가 정의한 것이고, 라벨이 내 맵에서 나온다 |
| 인식률 채점 분류기 | **자체** | 평가 도구. 작고 데이터가 내 것 |
| 풋홀드 추출·연결성 보정 | **AI 아님 (규칙, C++)** | 규칙으로 정확히 풀린다 — ADR-011 |
| 자연어 → `MapSpec` 파싱 | **기성** (Qwen2.5 Instruct GGUF) | 이미 풀린 문제. 재현해도 포트폴리오 가치가 없다 |
| 문법 제약 디코딩 | **기성** (llama.cpp GBNF) | 인프라 |
| 학습·추론 프레임워크 | **기성** (PyTorch / libtorch) | 인프라 |
| 문장 임베딩 (선택) | **기성** | 인프라 |

### 1.3 경계 규칙 — 기성 모델은 게임 런타임에 들어가지 않는다

**LLM은 에디터 전용 개발 도구다.** `GuideStoryGame.exe`는 LLM에 의존하지 않고, 배포물에 GGUF 파일이 포함되지 않는다.

ADR-009에서 "런타임 바이너리가 에디터 코드에 의존하지 않는다"고 정한 것의 연장이다. 게임이 실행되는 데 필요한 것은 **에디터가 저장한 `.gsmap` 파일** 하나뿐이라는 계약이 여기서도 유지된다. 수 GB짜리 모델이 게임 배포 표면에 들어오는 순간 이 계약이 깨진다.

자체 학습 모델(수 MB TorchScript)은 다르다 — 런타임 인게임 활용(예: 몬스터 행동)이 생기면 그때 엔진에 들어갈 수 있다. 크기와 결정론성이 다르기 때문이다.

## 2. ARCHITECTURE.md에 추가한 ADR

이 문서에서 발원한 결정은 **ADR-015**다 (내용은 [ARCHITECTURE.md](../ARCHITECTURE.md) §4 참조). 요약: AI 부품을 §1.1 기준으로 하이브리드 조달하고, 기성 모델은 에디터에만 둔다.

## 3. 실행 순서 — 6개 게이트

각 게이트는 **통과 조건**을 갖는다. 통과하지 못하면 다음으로 넘어가지 않는다.

```
G0 관통   에디터 AI 패널 ─ RemoteShapeGenerator ─[소켓]─ ai_server.py(스텁 래스터라이저)
          └─ 고스트 → 수락 → 풋홀드 추출(C++) → .gsmap          ★ ML 없이 전 경로 검증
                │
G1 데이터   gsmap.py ─┬─ synth_shapes.py ─┐
                     ├─ 손그림 수집 ──────┼─ build_dataset.py
                     └─ analyze 기반 통계 ┘
                │
G2 첫 모델  CVAE 학습 ─ eval ─ **스텁을 실모델로 교체**(파이썬 한 줄)   ★ 첫 진짜 데모
                │
G3 인프로세스 export.pt ─ TorchShapeGenerator(libtorch) ─ 지연 비교     ★ ADR-007 완료
                │
G4 조건부   MapSpec ─ 에디터 위젯 ─ analyze.py ─ 조건부 모델            ★ 단독 유용
                │
G5 자연어   llama.cpp + GBNF ─ 문장 → MapSpec
```

### G0 — 관통 (스텁으로 전 경로 연결) ☑ **통과** (2026-08-30)

| | |
|---|---|
| 만드는 것 | `src/ai/` 모듈 4종, `serve/ai_server.py`(스텁), 에디터 AI 패널, 풋홀드 추출, `GSMAP 3` 헤더 확장 |
| 마일스톤 | P-010 ~ P-013 |
| **통과 조건** | ① 키워드 입력 → 고스트 → Enter → **플레이 가능한 맵** ② AI 서버를 꺼도 에디터가 정상 동작 ③ 왕복 지연 측정값 기록 |
| 기간 | 약 2주 |

**왜 여기서 시작하는가.** 파서·데이터·모델은 지루하지만 결과가 예측 가능한 작업이다. 반대로 **C++↔Python 소켓이 에디터 UI까지 닿는 경로**는 스레드 모델·프레이밍·고스트 렌더·빌드 설정이 얽힌 미지수다. 위험한 곳을 먼저 뚫는다. 통합은 미룰수록 터진다.

**스텁이 곧 베이스라인이다.** 이 단계의 `ai_server.py`는 학습된 모델 대신 **절차적 도형 래스터라이저**로 격자를 만들어 돌려준다. ML 위험 0으로 전 경로가 검증되고, 이 래스터라이저는 버려지지 않는다 — [ai-shape-synthesis.md](ai-shape-synthesis.md) §5.2의 **비교 베이스라인**이자 §3.1의 **합성 데이터 생성기**로 그대로 쓰인다. 스텁 작업에 낭비가 없다.

**병행 작업**: `GSMAP 3`(모르는 헤더 키 스킵 + `CONCEPT`)을 이 단계에서 넣고, 손그림 수집을 곧바로 시작한다. 라벨 필드 없이 100장을 그리면 나중에 전부 다시 라벨링해야 한다.

### G1 — 데이터 토대 ★ 여기서 시작

| | |
|---|---|
| 만드는 것 | `tools/gsmap.py`, `tools/synth_shapes.py`(G0 스텁에서 승격), `tools/build_dataset.py`, 손그림 수집 완료 |
| 마일스톤 | P-014 ~ P-015 |
| **통과 조건** | ① `crystalgarden.gsmap` 왕복 바이트 동일 ② 합성 2,000장/라벨 ③ 손그림 라벨당 15장 이상, **하트는 합성 없이** |
| 기간 | 1~2주 |

> **손그림은 한 라벨 5장을 먼저 그려 파이프라인을 끝까지 통과시킨 뒤 나머지를 그린다.** 200장을 그려놓고 크롭·정규화가 안 맞는 걸 발견하면 전부 다시 그려야 한다.

### G2 — 첫 모델 ★ 스텁 교체

| | |
|---|---|
| 만드는 것 | `train/model.py`(CVAE), `train/train.py`, `train/classifier.py`, `train/eval.py` |
| 마일스톤 | P-016 |
| **통과 조건** | ① 인식률 ≥ 0.90 ② 다양성 붕괴 없음 ③ **하트가 나온다**(합성 시드 없이) ④ 래스터라이저 대비 비교표 ⑤ 에디터 코드 변경 없이 스텁 → 실모델 전환 |
| 기간 | 1~2주 |

⑤가 G0 설계가 옳았는지의 시험이다. **파이썬 서버의 생성 함수 하나만 바꿔서 에디터가 그대로 동작해야 한다.** C++을 건드려야 한다면 G0에서 계약을 잘못 그은 것이다.

### G3 — libtorch 인프로세스 ★ ADR-007 증명 과제 완료

| | |
|---|---|
| 만드는 것 | `train/export.py`, `src/ai/TorchShapeGenerator`(`#ifdef GUIDESTORY_WITH_TORCH`) |
| 마일스톤 | P-017 |
| **통과 조건** | ① 같은 인터페이스 뒤에서 두 구현이 교체 가능 ② **IPC vs 인프로세스 지연 비교표** ③ libtorch 없이도 빌드 성공 |
| 기간 | 약 1주 |

**여기서 멈춰도 포트폴리오가 완결된다.** ADR-007이 `☑`가 되고, "직접 설계·학습한 모델을 C++ 엔진에 통합하고 두 통합 방식의 지연을 비교했다"는 서사가 성립한다.

### G4 — 조건부 레벨 생성 ★ 단독으로 유용

| | |
|---|---|
| 만드는 것 | `MapSpec` 스키마, 에디터 조건 위젯, `tools/analyze.py`, 조건부 CVAE |
| 마일스톤 | P-018 ~ P-022 |
| **통과 조건** | ① **위젯만으로**(LLM 없이) 맵 생성 완결 ② 분석기 라벨 타당성 검증 ③ **응답성 — 슬라이더를 올리면 측정값이 단조 증가** ④ 플레이 가능성 ≥ 0.85 |
| 기간 | 3~4주 |

내부 순서를 지킨다: **스키마 → 위젯 → 분석기 → 모델**.

### G5 — 자연어

| | |
|---|---|
| 만드는 것 | llama.cpp 서버 + GBNF 문법, few-shot 프롬프트, 홀드아웃 50문장 평가 |
| 마일스톤 | P-023 ~ P-024 |
| **통과 조건** | ① 문법 제약으로 파싱 실패 0 ② 손으로 쓴 홀드아웃 필드 정확도 리포트 ③ LLM 실패 시 위젯으로 자동 폴백 |
| 기간 | 약 2주 |

파인튜닝은 여기 포함되지 않는다. 문법 제약 + few-shot 정확도를 **먼저 측정하고**, 부족할 때만 LoRA로 간다.
