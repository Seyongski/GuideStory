# ai-level-generation.md — 자연어 조건 레벨 생성 (2단계)

> **한 줄 정의**: `"차가운 얼음동굴, 아래쪽은 물, 발판은 드문드문"` 을 받아 플레이 가능한 맵을 생성한다.

> 관련: [ARCHITECTURE.md](../ARCHITECTURE.md) ADR-007 · [PLANS.md](../PLANS.md) 2.5단계 · [GuideStoryAI/README.md](../GuideStoryAI/README.md)
> **진행 순서**: [ai-roadmap.md](ai-roadmap.md) — 조달 원칙(ADR-015)과 게이트별 실행 순서. 이 문서의 내용은 G4~G5에 해당한다.

## 0. 이것은 1단계의 확장이 아니라 다른 과제다

"자연어 파서만 앞에 붙이면 된다"고 생각하면 실패한다. 바뀌는 것은 입력이 아니라 **출력 공간과 채점 방법**이다.

| | 1단계 — 도형 생성 | 2단계 — 레벨 생성 |
|---|---|---|
| 입력 | 닫힌 라벨 6개 | 다속성 조건 (테마 × 재질 × 밀도 × 수직성 × 공간 조건) |
| 출력 | 32×32 격자, 도형 하나 | 64×32 격자 + 풋홀드 + 스폰 = 플레이 가능한 맵 |
| **정답** | **있다** — 레퍼런스 하트와 비교 | **없다** — "좋은 얼음동굴"의 정답 맵은 존재하지 않는다 |
| 채점 | IoU, 인식률 | ??? ← **이걸 먼저 정의해야 한다** |
| 실패 모드 | 하트처럼 안 보임 | 예쁜데 못 놂 / 조건을 무시함 |

**정답이 없다는 것이 2단계의 전부다.** 채점할 수 없으면 학습도 개선도 없다. 그래서 이 문서의 절반은 §3(역방향 라벨링)과 §5(조건 준수도)에 쓴다 — 모델 이야기는 그다음이다.

## 1. 3층으로 자른다

한 덩어리로 만들면 "결과가 이상할 때 누구 잘못인지" 알 수 없다.

```
"차가운 얼음동굴, 아래쪽은 물, 발판은 드문드문"
   │
   ▼  ① 의도 파싱 — 로컬 LLM (기성 모델, 학습 안 함)
MapSpec (JSON)  ←──── 에디터 위젯도 똑같은 JSON을 만든다 (§2)
   │
   ▼  ② 조건부 생성 — 내가 학습시킨 모델
타일 격자 64×32
   │
   ▼  ③ 후처리 — 결정론적 규칙 (ADR-011)
풋홀드 · 스폰 · 연결성 보정 → .gsmap
```

- **①은 타일 근처에 가지 않는다.** LLM의 책임은 문장 → JSON 한 번뿐이다.
- **②는 자연어를 모른다.** 숫자와 범주형 조건만 받는다.
- **③은 1단계에서 이미 만든 것**을 그대로 쓴다 (`tools/footholds.py`).

이 분리 덕분에 실패를 격리해서 잴 수 있다 — LLM은 JSON 필드 정확도로, 생성 모델은 조건 준수도로, 후처리는 플레이 가능성으로. 이게 ADR-011("생성 모델과 결정론적 후처리를 분리한다")을 한 층 더 밀어붙인 형태다.

## 2. MapSpec — 계약이자 가장 먼저 만들 것

### 2.1 스키마

```json
{
  "theme": "ice_cave",
  "tiles": { "ground": 3, "accent": 5 },
  "layout": {
    "platform_density": 0.25,
    "verticality":      0.70,
    "openness":         0.60,
    "gap_width":        0.55
  },
  "regions": [
    { "where": "bottom", "extent": 0.20, "fill": "water" }
  ],
  "size": [50, 29],
  "seed": 20260828
}
```

| 필드 | 형태 | 자연어 예시 |
|---|---|---|
| `theme` | 범주형 (초원/동굴/얼음동굴/용암/폐허/수중) | "차가운 얼음동굴" |
| `tiles` | 팔레트 id 매핑 | 테마에서 기본값 유도, 사용자가 덮어쓰기 가능 |
| `platform_density` | 0..1 | "발판은 드문드문" → 0.25 |
| `verticality` | 0..1 | "위로 올라가는 구조" → 0.8 |
| `openness` | 0..1 | "좁은 통로" → 0.2 |
| `gap_width` | 0..1 | "점프가 빡세게" → 0.8 |
| `regions[]` | 공간 조건 | **"아래쪽은 물"** |

`regions`가 없으면 스칼라 조건만으로는 **"아래쪽은"** 같은 위치 지정을 표현할 수 없다. 이 배열은 §4에서 **2D 조건 마스크 채널**로 렌더링되어 생성기에 들어간다.

### 2.2 JSON을 먼저 정하는 이유 세 가지

1. **학습 모델의 조건 공간이 곧 이 스키마다.** 필드를 정하기 전엔 어떤 데이터가 필요한지 알 수 없다.
2. **평가가 분리된다.** LLM은 "문장 → 올바른 JSON" 정확도로, 생성 모델은 "JSON → 그대로 지킨 맵" 준수도로 따로 채점된다.
3. **LLM 없이도 기능이 완성된다.** ← 가장 중요하다.

### 2.3 위젯이 먼저, LLM은 나중 — 이 순서를 반드시 지킨다

에디터 AI 패널에 **슬라이더와 드롭다운**을 먼저 만든다. 그 위젯들이 만들어내는 것이 바로 MapSpec JSON이다.

```
[테마 ▾ 얼음동굴]  [발판 밀도 ──●─────]  [수직성 ───────●─]
[영역 조건: 아래 20% = 물  ✕]  [+ 영역 추가]
[ 생성 ]                        ← 여기까지가 LLM 없이 동작하는 완성품

[자연어로 입력: "차가운 얼음동굴, 아래쪽은 물..."] [채우기]  ← 나중에 얹는 층
```

**LLM은 위젯을 자동으로 채워주는 입력 보조 도구**일 뿐이다. 이렇게 만들면:

- LLM 서버가 없어도, 문장을 잘못 알아들어도 기능이 죽지 않는다.
- LLM이 틀리면 사용자가 슬라이더 하나만 고치면 된다 — 블랙박스가 아니다.
- ADR-010("AI는 제안하고 사람이 확정")이 **파싱 단계까지** 확장된다. 파싱 결과 자체가 수정 가능한 제안이다.
- 위젯 값을 랜덤 샘플링하면 그대로 **학습·평가용 스펙 생성기**가 된다.

## 3. 데이터 — 역방향 라벨링이 2단계의 핵심 아이디어

### 3.1 문제

1단계는 "하트 40장 그리기"로 끝났다. 2단계에서 같은 방식을 쓰면 `테마 6 × 밀도 5 × 수직성 5 × 개방도 5 × 영역조건 N` 조합마다 맵을 그려야 한다. **불가능하다.**

### 3.2 해법 — 스펙에 맞춰 그리지 말고, 그린 것에서 스펙을 측정한다

`MapSpec`의 레이아웃 필드는 전부 **맵에서 계산 가능한 양**이다.

```
tools/analyze.py :  .gsmap  →  MapSpec
```

| 필드 | 계산 방법 |
|---|---|
| `platform_density` | 풋홀드 총 길이 ÷ (맵 폭 × 층 수) |
| `verticality` | 풋홀드 y좌표의 표준편차 ÷ 맵 높이 |
| `openness` | 빈 칸 연결 컴포넌트의 평균 크기 ÷ 전체 빈 칸 |
| `gap_width` | 인접 풋홀드 간 수평 간격의 중앙값 ÷ 타일 크기 |
| `regions[]` | 타일 종류별 비율 + 무게중심 y ("물이 아래쪽에 몰려 있는가") |
| `theme` | 타일 히스토그램 |

**이러면 지금까지 그린 모든 맵과 앞으로 그릴 모든 맵이 자동으로 라벨링된다.** `crystalgarden.gsmap`도 학습 데이터가 된다. 손으로 라벨을 붙이는 작업이 통째로 사라진다.

그리고 절차적 맵 생성기(1단계의 `synth_shapes.py`를 레벨용으로 확장)는 **생성 파라미터가 곧 정답 라벨**이므로, 합성 데이터는 라벨링이 아예 필요 없다.

### 3.3 자기 채점 위험 — 반드시 인지할 것

라벨을 `analyze.py`로 붙이고 평가도 `analyze.py`로 하면, 측정하는 건 "조건을 지켰는가"가 아니라 **"내 분석기를 속이는 법을 배웠는가"** 다. 1단계의 래스터라이저 비판(ai-shape-synthesis.md §3.3)과 같은 구조의 함정이다.

완화 세 가지:

1. **홀드아웃 손그림 맵** — 학습에 쓰지 않은 내 맵의 분석값과 모델 조건부 생성 결과를 비교.
2. **사람 평가** — 20장을 눈으로 보고 스펙과 맞는지 판정. 소규모여도 반드시 리포트에 넣는다.
3. **플레이 가능성** — 분석기와 **독립적인** 지표. 실제 점프 모델로 스폰에서 도달 가능한 발판 비율을 시뮬레이션으로 잰다. 분석기를 속여도 이건 못 속인다.

## 4. 조건부 생성 모델 v2 — 1단계의 재작성이 아니다

1단계 CVAE에 조건 입력 두 종류를 더한 것이다. 인코더/디코더 골격은 그대로 간다.

```
정규 격자: 64×32 (맵 50×29를 덮는 최소 2의 거듭제곱 격자, 패딩/크롭)

디코더 입력:
  z (16)                              ← 잠재 변수, 변형 생성
  ⊕ scalar_cond (broadcast)           ← density/verticality/openness/gap_width + theme 임베딩
  ⊕ spatial_mask (C채널 2D)           ← regions[]를 렌더링한 마스크. "아래쪽 20%는 물"
  → ConvTranspose 스택 → 64×32×6 logits
```

- **스칼라 조건은 broadcast**해서 모든 위치에 같은 값으로 깔고, **공간 조건은 채널로 concat**한다. 위치별로 다른 지시("여기는 물")는 마스크 채널이 아니면 전달할 방법이 없다.
- 조건 무시(condition collapse)를 막기 위해 **조건 드롭아웃**(학습 중 10% 확률로 조건을 지움)을 넣고, 추론 시 조건 있음/없음 출력을 외삽하는 방식(classifier-free guidance)으로 조건 강도를 조절한다. 이 한 가지 장치로 "슬라이더를 움직여도 결과가 안 변한다"는 가장 흔한 실패를 막는다.
- 1단계 CVAE 체크포인트로 **초기화**한다. 도형 감각을 이미 배운 상태에서 시작한다.

> **v3 자기회귀 트랜스포머로 갈 때의 이점**: 조건을 프리픽스 토큰으로 넣으면 부분 맵 완성(인페인팅)이 그대로 열린다 — "내가 왼쪽 절반을 그렸으니 오른쪽을 같은 느낌으로 채워줘". 여기서 1단계 §1의 A안이 최종 형태로 실현된다.

## 5. 평가 — IoU를 대체하는 것

### 5.1 조건 준수도 (Condition Adherence)

정답 맵이 없으므로 **왕복으로 잰다**.

```
목표 MapSpec  →  생성  →  analyze.py  →  측정된 MapSpec
                              └─ 필드별 오차를 비교
```

| 지표 | 정의 | 목표 |
|---|---|---|
| 스칼라 준수도 | `platform_density` 등 4개 필드의 평균 절대 오차 | ≤ 0.10 |
| 테마 일치 | 타일 히스토그램 기반 테마 분류 정확도 | ≥ 0.90 |
| 공간 조건 만족 | `regions[]` 지정 영역의 실제 채움 비율 | ≥ 0.80 |
| **응답성** | 슬라이더를 0.2→0.8로 올렸을 때 측정값이 **단조 증가**하는가 | 전 필드 만족 |
| 플레이 가능성 | 스폰에서 도달 가능한 발판 비율 (독립 시뮬레이션) | ≥ 0.85 |
| 다양성 | 같은 스펙·다른 seed 50장의 pairwise 거리 | 붕괴 아님 |

**응답성이 실질적으로 가장 중요한 지표다.** 평균 오차가 낮아도 슬라이더에 반응하지 않으면 조건부 생성이 아니라 그냥 평균적인 맵을 뽑는 것이다.

### 5.2 LLM 레이어는 따로 잰다

손으로 쓴 한국어 문장 50개 + 손으로 쓴 정답 JSON 50개를 홀드아웃으로 두고 **필드 단위 정확도**를 잰다. 범주형은 일치율, 스칼라는 절대 오차(±0.15 이내면 정답 처리 — 사람도 "드문드문"을 0.25로 쓸지 0.30으로 쓸지 합의할 수 없다).

### 5.3 베이스라인

1단계와 같은 규칙이다. **절차적 레벨 생성기와 나란히 싣는다.** 조건 준수도는 절차 생성기가 이길 가능성이 높다(파라미터를 직접 넣으니 당연하다). 모델이 이겨야 하는 축은 **다양성 · 손그림 스타일 재현 · 부분 완성 · 조건 조합의 외삽**이다. 지는 칸을 표에서 지우지 않는다.

## 6. LLM 레이어

### 6.1 구성

| 항목 | 선택 | 이유 |
|---|---|---|
| 모델 | Qwen2.5 7B Instruct (GGUF) — 느리면 3B | 한국어 품질 대비 로컬 실행 가능 |
| 런타임 | llama.cpp 서버 | GBNF 문법 제약 지원 |
| 출력 강제 | **GBNF grammar로 MapSpec 스키마 강제** | 파싱 실패·재시도 루프가 원천 제거된다 |
| 프롬프트 | few-shot 15~20쌍 | 파인튜닝 전에 여기까지 먼저 |
| 지연 예산 | 1~3초 | 맵 생성당 1회. 붓질 루프 안이 아니라 허용된다 |

**GBNF 문법 제약이 이 레이어의 핵심 기술 선택이다.** 프롬프트로 "JSON만 출력해"라고 부탁하는 것과, 디코딩 단계에서 문법에 맞는 토큰만 허용하는 것은 다르다. 후자는 유효하지 않은 JSON이 나올 수 없다.

> **이 층만 기성 모델을 쓴다** (ADR-015, [ai-roadmap.md](ai-roadmap.md) §1). 그리고 **에디터 전용**이다 — `GuideStoryGame.exe` 배포물에 GGUF 파일은 포함되지 않는다.

### 6.2 파인튜닝은 나중이다 — 그리고 데이터는 역번역으로 만든다

문법 제약 + few-shot으로 §5.2 정확도를 먼저 측정한다. 부족할 때만 LoRA로 간다.

그때 학습 데이터는 **반대 방향으로** 만든다. `MapSpec → 한국어 설명`은 LLM이 쉽게 하는 일이다.

```
위젯 공간에서 스펙 랜덤 샘플링  →  LLM이 그 스펙을 묘사하는 한국어 문장 생성
                                 →  (문장, 스펙) 쌍 300개  →  LoRA 학습
```

사람은 검수만 한다. 다만 이렇게 만든 데이터는 **LLM 자신의 어투에 치우친다** — 내가 실제로 칠 문장과 다르다. 그래서 §5.2의 홀드아웃 50개는 반드시 **내가 직접 손으로 쓴다.**

### 6.3 거절 정책

LLM이 추측하게 두지 않는다.

- 알 수 없는 필드는 **채우지 말고 비운다**. 에디터가 기본값 위젯으로 표시한다.
- 지원하지 않는 테마("우주정거장")는 `null` + 사유. 임의로 가까운 테마에 매핑하지 않는다.
- 파싱 성공률·필드별 신뢰도를 로그에 남긴다. 자주 비는 필드가 곧 다음 few-shot 예시의 대상이다.

## 7. ARCHITECTURE.md에 추가할 ADR 초안

### ADR-013 — 자연어는 구조화된 스펙을 거쳐서만 생성기에 닿는다

- **결정**: LLM은 자연어 → `MapSpec` JSON 변환만 담당한다. 생성 모델은 JSON만 받고 자연어를 보지 않는다. 스펙은 사용자가 위젯으로 수정 가능한 중간 산출물로 노출된다.
- **이유**: 실패 지점 분리(파싱 오류 / 생성 품질 / 후처리 오류를 각각 잰다). LLM이 없거나 실패해도 위젯 경로로 기능이 완결된다. 자연어를 직접 조건으로 넣으면 조건 준수도를 정의할 수 없다.
- **트레이드오프**: 스키마에 없는 뉘앙스는 표현할 수 없다("음산한 느낌"). 스키마 확장마다 위젯·학습 조건·분석기를 함께 고쳐야 한다(3곳 동기화 비용).
- **증명 과제**: LLM 필드 정확도와 생성 조건 준수도를 **분리해서** 측정. 위젯 단독 경로가 LLM 없이 완결됨을 검증.

### ADR-014 — 학습 라벨을 손으로 붙이지 않고 맵에서 측정한다

- **결정**: `tools/analyze.py`가 `.gsmap`에서 레이아웃 속성을 계산해 라벨로 쓴다. 스펙에 맞춰 맵을 그리는 것이 아니라, 그린 맵에서 스펙을 역산한다.
- **이유**: 조건 조합 수만큼 맵을 그리는 것은 불가능하다. 이 방식이면 기존 맵과 앞으로 그릴 모든 맵이 자동으로 학습 데이터가 된다.
- **트레이드오프**: 분석기가 정의한 것만 조건이 될 수 있다. 라벨과 평가가 같은 함수라 **자기 채점 위험**이 있다(§3.3) — 홀드아웃·사람 평가·독립 플레이 가능성 지표로 완화한다.
- **증명 과제**: 분석기 라벨의 타당성 검증(내가 의도한 밀도와 측정값의 상관), 자기 채점 완화 3종 결과 기록.

이 문서가 다루는 범위는 **P-018 ~ P-024 (게이트 G4~G5)** 이고, 순서상 지켜야 할 점만 옮겨 적는다.
