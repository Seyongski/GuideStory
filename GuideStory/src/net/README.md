# net/ — 네트워크 (ADR-001)

클라이언트 쪽 네트워크 계층. 서버 본체는 [`GuideStoryServer/`](../../../GuideStoryServer/README.md) 에 있다.

| 파일 | 역할 | 누가 컴파일하나 |
|------|------|-----------------|
| `Protocol.h` | 옵코드·바디 구조체·결과 코드. **서버와 클라이언트의 유일한 계약** | 양쪽 |
| `Framing.h/.cpp` | 길이 프리픽스 프레이밍(TCP 경계 복원) | 양쪽 |
| `Socket.h` | WinSock / POSIX 차이 흡수 | 양쪽 |
| `NetClient.h/.cpp` | 워커 스레드 + 큐. 게임 스레드는 소켓을 만지지 않는다 | 클라이언트 |
| `ServerConfig.h` | 접속 주소(`assets/config/server.txt`) | 클라이언트 |

## 규칙

- **프로토콜은 헤더 하나를 공유한다.** 서버와 클라이언트가 각자 정의를 들고 있으면 한쪽만
  고쳤을 때 조용히 어긋난다(패킷은 도착하는데 엉뚱하게 해석된다).
- **net 은 SDL 을 모른다** (ADR-006). `Protocol.h` 는 `<cstdint>` 만 쓰고,
  `Socket.h`(winsock2.h) 는 SDL 을 쓰는 TU 에 섞이지 않도록 `NetClient.cpp` 안에만 들어간다.
- **비정상 패킷은 거부·로깅한다** ([RELIABILITY.md](../../../RELIABILITY.md) §2.2).
  선언된 `BodySize`/`TextLen` 을 신뢰하기 전에 상한과 실제 도착 길이를 검사한다.
- **스레드 경계**: 워커는 순수 데이터(`NetEvent`)만 큐에 넣고, 게임 스레드가 `Poll()` 로
  꺼내 화면을 바꾼다. 워커에서 화면/월드를 건드리면 재현이 어려운 크래시가 난다.

## 다음 단계

지금 서버가 아는 것은 "누가 접속해 있는가" 까지다. 서버 권위 이동/충돌 판정은
서버가 월드 상태를 가진 뒤의 일이고, 그때 옵코드를 `Protocol.h` **끝에** 붙여서 늘린다.
IOCP vs Select 비교(ADR-001 증명 과제)의 기준선은 현재의 접속당 스레드 하나 모델이다.
